# Task format

A Task is **one unit of real building-engineering work, plus the means to grade
it**. It is a contract, not a description: if the grader can check it, the prompt
must have said it.

## The seven dimensions

Every Task is defined across these, and each carries a *state* —
`clear` · `needs_clarification` · `not_provided` · `not_applicable` — never a
score.

| # | Dimension | The question it answers |
|---|---|---|
| 1 | **Objective** | What should the agent accomplish? The goal and scope, not the method. |
| 2 | **Inputs & Resources** | What does the agent receive? Data, files, models, geometry, drawings, weather, code, documents, APIs, databases. |
| 3 | **Detailed Instruction** | How would an experienced human work through this? The procedure, checks and reasoning. |
| 4 | **Environment & Access** | What tools, software, systems or compute may it use — and what is prohibited? |
| 5 | **Reproducibility** | What must be *fixed* so results are reproducible and fairly comparable? |
| 6 | **Deliverables** | What comes back? File names, formats, columns, structure. |
| 7 | **Evaluation** | How is success decided? Checks, metric, ground truth, baseline, human reference. |

## Two separations that matter

**Detailed Instruction is not the prompt.** It is a required Task artifact, and
it is deliberately excluded from the canonical prompt an agent receives, because
the benchmark runs `Task` and `Task + Detailed Instruction` as separate
conditions. A prompt carrying the procedure would collapse them.

**Reproducibility is not the solution method.** A model, a window length or an
algorithm named by the contributor is only a Task condition when the comparison
would be unfair without it. Otherwise it belongs in the Detailed Instruction and
the agent must stay free to choose. When it is ambiguous, the workflow asks.

## What is published and what is not

Public: the canonical prompt, the structured definition, the original human
request, input files, provenance.

Held on the hub: the Detailed Instruction, the evaluation criteria, and every
ground-truth or human-reference artifact. An agent that could read those would
not be measured on the Task, only on its memory of the answer.

## Metadata collected up front

Title · Domain (one of the closed eight) · Difficulty (easy/medium/hard/expert) ·
Estimated Human Effort (1 day … 3 months, longer) · Task Familiarity
(new … expert) · Agentic AI Familiarity (new … builder).

The Task ID (`BXT-000123`) is generated by the hub. Never invent one.

## Multiple instances

Cases sharing an objective, an input/output structure, a reproducibility
protocol and an evaluation method belong under **one Task as instances**, not as
duplicated Tasks. The benchmark runs every condition against every instance.

## The interaction history

Every question, answer, edit and state change during definition is kept, along
with the contributor's familiarity answers and how long it took. Nothing is
overwritten, including the first words the contributor wrote. It is what lets
Buildrix later ask which parts of a task humans naturally leave out.
